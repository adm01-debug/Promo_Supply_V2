
## Plan: Add `/admin/dependency-health` report page

### Goal
Surface a concise in-app report showing the pinned `date-fns` version and a clear verdict on whether lockfile drift is being detected during installs — so the team has a visible signal without needing to read CI logs.

### Approach
Static admin page (admin-only route). The browser cannot read `node_modules` or `bun.lock` at runtime, so the page reads from a small JSON snapshot file generated by the existing `scripts/ci-check.sh` flow. No backend, no edge function — pure static asset + read.

### Changes

**1. New file — `public/dependency-health.json`** (committed snapshot, refreshed by CI)
```json
{
  "generatedAt": "2026-04-21T00:00:00Z",
  "dateFns": {
    "spec": "3.6.0",
    "installed": "3.6.0",
    "locked": "3.6.0",
    "exactPinned": true
  },
  "lockfileDrift": {
    "detected": false,
    "lastCheckedAt": "2026-04-21T00:00:00Z",
    "source": "bun install --frozen-lockfile"
  }
}
```

**2. Update `scripts/ci-check.sh`** — append a step that writes `public/dependency-health.json` after a successful frozen install + type-check:
- Read `spec` from `package.json`, `installed` from `node_modules/date-fns/package.json`, `locked` from `bun.lock`.
- `lockfileDrift.detected = false` when `bun install --frozen-lockfile` succeeded; the script never reaches the JSON write step otherwise (so `true` is only ever written manually if needed).
- Stamp `generatedAt` / `lastCheckedAt` with `date -u +%FT%TZ`.

**3. New file — `src/pages/admin/DependencyHealth.tsx`** (~120 lines)
- Fetches `/dependency-health.json` on mount via `useQuery`.
- Renders one `Card` with three sections:
  - **date-fns version** — large badge with `installed` version, smaller row showing `spec` / `locked` / `installed` side-by-side. Green check if all three match, red alert if not.
  - **Lockfile drift** — green "No drift detected" badge or red "Drift detected" alert, with the `lastCheckedAt` timestamp + source command.
  - **Generated at** — relative time ("2 hours ago") + absolute UTC.
- Uses existing `Card`, `Badge`, semantic tokens. Dark Premium theme, dense spacing (`space-y-4`).
- Empty/error state: if JSON missing or fails to parse, shows "Run `bun run ci:check` to generate this report."

**4. Wire route in `src/routes/AppRoutes.tsx`**
- Lazy import `DependencyHealth`.
- Add route `/admin/dependency-health` wrapped in `ProtectedRoute requiredRole="admin"` + `ModuleErrorBoundary module="default"` (matches existing `/admin/telemetria` pattern).

### Why this shape
- Browser-side static read is the simplest mechanism — no edge function, no DB, no realtime needed for a once-per-CI-run snapshot.
- Snapshot in `public/` is automatically served, versioned in git, and visible in PR diffs (drift becomes a code-review signal too).
- Admin-gated to match the existing `/admin/telemetria` and `/auditoria` access policy.

### Verification
1. Run `bun run ci:check` → confirm `public/dependency-health.json` is written with `spec=installed=locked=3.6.0` and `lockfileDrift.detected=false`.
2. Navigate to `/admin/dependency-health` as admin → confirm green checkmarks, version `3.6.0` displayed, "No drift detected" badge.
3. Navigate as non-admin → `ProtectedRoute` redirects/blocks (existing behavior).
4. Sanity check: temporarily edit the JSON to set `lockfileDrift.detected: true` → confirm the page renders the red alert state → revert.
5. `npx tsc --noEmit -p tsconfig.app.json` → 0 errors.
6. `npx eslint .` → clean (no `date-fns` barrel imports introduced).

### Risk / scope
- New page + new route + 1 new public asset + 1 script append. No dependency, schema, or runtime behavior changes elsewhere.
- File size: page kept under the 400-line limit.
- Snapshot is read-only at runtime — no security surface.

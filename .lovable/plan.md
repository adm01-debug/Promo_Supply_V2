
## Plan: Auto-generate date-fns smoke test from real `src/` usage

### Goal
Replace the hand-maintained import list in `src/test/dateFns.smoke.test.ts` with a generated one, sourced from a scan of every `date-fns/*` subpath import actually used in `src/`. This way, when a new helper or locale is introduced anywhere in the app, the smoke test automatically covers it on the next CI run — no manual sync, no drift.

### Approach
A small Node script walks `src/`, parses every `import ... from "date-fns/<subpath>"`, deduplicates the named exports per subpath, and rewrites `src/test/dateFns.smoke.test.ts` from a deterministic template. The script is wired into `scripts/ci-check.sh` so it runs **before** the smoke test step — guaranteeing the test always reflects current usage.

### Changes

**1. New file — `scripts/generate-datefns-smoke-test.mjs`** (~150 lines, plain Node, no deps)
- Recursively walks `src/` using `fs.readdir` (excludes `src/test/`, `node_modules`, `.git`, `dist`).
- Reads every `.ts` / `.tsx` file.
- Regex-matches two import shapes:
  - `import { a, b as c } from "date-fns/<subpath>"` → captures subpath + named imports
  - `import { x } from "date-fns/locale/<locale>"` → captures locale subpath + named imports
- Builds a `Map<subpath, Set<namedImport>>`.
- Sorts subpaths and names alphabetically for deterministic output.
- Writes `src/test/dateFns.smoke.test.ts` from a template:
  - Header comment: `// AUTO-GENERATED by scripts/generate-datefns-smoke-test.mjs — do not edit by hand. Run `node scripts/generate-datefns-smoke-test.mjs` to refresh.`
  - One `import` line per subpath.
  - Three preserved test blocks:
    1. **All imports are functions** — iterates `[fn1, fn2, ...]`, asserts `typeof === "function"` (skips locale objects).
    2. **Locale objects are valid** — for each imported locale, asserts it's a non-null object with a `.code` string.
    3. **Smoke-format with each locale** — `format(ref, "dd/MM/yyyy", { locale })` returns a `dd/MM/yyyy` string for every imported locale.
  - The fixed `ref = new Date("2025-01-15T12:00:00Z")` constant.
- Exits non-zero if zero subpaths are found (catches accidental scan misconfigurations).
- Logs a summary: `Generated smoke test for N subpaths, M named exports, K locales.`

**2. Update `scripts/ci-check.sh`** — insert one step before the existing smoke-test step. Renumber banners to `[1/6] … [6/6]`:

```bash
echo "▶ [4/6] Regenerating date-fns smoke test from src/ usage..."
node scripts/generate-datefns-smoke-test.mjs

echo "▶ [5/6] Running date-fns smoke test..."
npx vitest run src/test/dateFns.smoke.test.ts --reporter=verbose
```

Final flow: clean → install → tsc → **generate** → vitest → snapshot.

Because `set -euo pipefail` is active, if generation fails (e.g. zero subpaths found, or write error), CI stops before the test runs.

**3. `src/test/dateFns.smoke.test.ts`** — first run of the script overwrites this file. Going forward it's a generated artifact (still committed, so PR diffs surface coverage changes).

### Why this design
- **Single source of truth**: actual `src/` imports drive the test — impossible for the smoke test to fall behind real usage.
- **Pure Node, zero deps**: no AST parser, no `ts-morph`. Regex is sufficient because the ESLint rule `no-restricted-imports` already forbids the barrel form, so every `date-fns` import in `src/` is guaranteed to be a subpath import with a simple shape.
- **Deterministic output**: sorted alphabetically → stable git diffs, easy code review.
- **Committed output**: PR reviewers see when new subpaths/locales enter the test, which doubles as a usage audit trail.
- **CI runs generation BEFORE the test**: any drift between committed test file and current `src/` usage is auto-corrected at CI time. If a contributor forgets to run the script locally, CI still passes (and the diff shows up as an uncommitted change in `git status`, which a follow-up CI step or pre-commit hook could enforce later — out of scope for this plan).

### Edge cases handled
- Multi-line imports (`import {\n  a,\n  b,\n} from "date-fns/format"`) → regex uses `[\s\S]*?` for the brace contents.
- Aliased imports (`import { format as fmt } from "date-fns/format"`) → strip the ` as alias` portion, keep the original export name (that's what we test).
- Type-only imports (`import type { Locale } from "date-fns/locale/pt-BR"`) → skipped (we can't test types at runtime). Detected by `import type` prefix.
- Side-effect imports (`import "date-fns/something"`) → skipped (no named exports to test).
- Duplicate imports across files → deduplicated by the `Set`.

### Verification
1. Run `node scripts/generate-datefns-smoke-test.mjs` locally → expect `src/test/dateFns.smoke.test.ts` rewritten with the AUTO-GENERATED header, summary log printed, exit 0.
2. `npx vitest run src/test/dateFns.smoke.test.ts --reporter=verbose` → all generated tests pass.
3. `npx tsc --noEmit -p tsconfig.app.json` → 0 errors (test file still type-checks).
4. `npx eslint .` → clean (generated file uses subpath imports only).
5. Sanity check: add `import { addYears } from "date-fns/addYears"` to any `src/` file → rerun script → confirm `addYears` now appears in the generated test → revert.
6. Run full `bash scripts/ci-check.sh` → expect 6 numbered steps, smoke test green, snapshot written, final `✅`.

### Risk / scope
- One new script + one CI script edit + one test file becomes generated. No source, dependency, schema, or runtime changes.
- Adds <1s to CI (single filesystem walk over `src/`).
- The test file is now generated; manual edits to it will be overwritten on the next CI run. The header comment makes this explicit.
